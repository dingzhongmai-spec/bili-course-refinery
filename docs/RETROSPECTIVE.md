# 上一个任务的流程复盘

来源：2026-10-08至09的任务「确认工具仓库可正常运行」。本次回顾读取了可用会话记录、用户消息、最终TeX，以及用户允许查看的回收站脚本与审阅说明。这里是流程归纳，不附原始聊天、个人账号或整个执行日志。

## 对话如何推动要求收敛

|阶段|用户要求与实际变化|可复用规则|
|---|---|---|
|环境|先检查下载工具仓库可否运行，明确不用虚拟环境|先验证已有工具；解释器与依赖一致|
|输入障碍|仅有作者、标题和合集不足；用户要求“利用工具完成工作”|内容读取失败先换取得渠道，不虚构已观看|
|采集|解析课程目录，取得公开音视频，字幕探测后采用本地ASR与板书抽帧|清单、口述、板书三个层面分别记录|
|持续处理|多次“继续”，期间发生使用限额与上下文中断|进度落盘、按条目继续，完成状态不能靠会话记忆|
|审阅原则|“最简单的，最直接的，简单大于直接”；允许本地Wolfram或插件核验|按知识、计算、分支、可验证性比较路线|
|初版|形成方法、条件、代表题和离线HTML/Markdown；完成五轮记录|内容和展示均需实际检查|
|扩写|用户指出解释过于简略，要求每个方法有自己的解释，转LaTeX/PDF|摘要不够；解释选择依据与原理，区分作者与整理者|
|编辑器问题|用户要求修复内置编译；处理TeX后仍需独立诊断编译渠道|源代码问题与服务故障分别报告|
|排版再修订|参考本地数学建模模板，“所有公式都要标出”|样式提前确定，独立公式编号，长式合理分行|
|推导|“每个推导摘要必须给出必要的思维链路”|给公开可检验的推导依据与计算，避免只写答案|
|图像|必要时用本地Wolfram绘图|图为解释服务，标参数并保留计算依据|
|最终验收|用户明确本地编译并用SumatraPDF查看|PDF阅读器与编译器分工明确，验收真实产物|
|清理|先要求完成后清理视频，最后要求清理一代/二代材料，仅留最终PDF和TeX|分阶段授权、先验收再回收、明确保留依赖|

## 从记录能确认的结果

最终TeX说明正文覆盖新系列合集的63节（基础33、进阶30），226条方法与142道代表题；旧系列15节未纳入逐节正文。此前读取完整自动转写并检查120秒板书总览；不能称为逐帧观看全部课程。

审阅记录写明72项选定Wolfram检查通过。这个数表示部分公式和步骤的计算核验，不表示142题都被CAS完整证明。初版记录284处HTML公式渲染成功、目录与窄屏检查；它也不代表后来PDF自动通过。

最终目录实际只剩PDF与对应TeX。源稿包含内容取得方式、解释归属和核验边界。原采集与审阅脚本可在回收站读取，本包仅据此归纳，未把课程原始材料恢复进上传包。

## 需要避免的历史实现局限

- 原脚本写死作者、合集、个人Python与模型快照路径，不适合换课程直接运行。
- 原采集以文件存在/大小和结束日志判断进展，不能替代逐条媒体完整性验证。
- 原板书总览把时间标为近似值；关键题应保存真实定位，不把120秒粗采样当作充分覆盖。
- 自动转写对指数、负号、常数和术语有误录风险，整理者也会抄错。应将“原课疑点”和“本稿错误”分别记录。
- 初版解释不足导致二次大规模扩写；内容模板应一开始就要求理由、条件和必要推导。
- 生成脚本与手工修订主稿可能相互覆盖；明确唯一主稿与生成器边界。
- 某一版的渲染验收不能继承给下一版；最终修改后重新检查受影响内容和输出。

## 可推广的纠错范型

|风险|检查方式|为什么有效|
|---|---|---|
|除以未知函数丢失常数/零解|先单列因子为零情况，代回原方程|代数变形不再遗漏分支|
|路径方向导致积分符号错|独立参数化与定理路线对照|不同表示能暴露方向错误|
|指数原题抄错|原题板书回查，再重算|不能用错误题面的正确计算自证|
|量词口述不严谨|展开定义、构造反例|“存在”和“任意”差别得到可检验说明|
|直接法复杂|试最小换元、恒等式或初等估计|减少额外知识与无关结论|

这些是归纳规则，具体课程结论仍需逐题核验，不能以历史经验替代本次证据。
